- **`Program.cs`**: Main source file where the C# code of the application is written.
- **`obj/`**: Contains temporary and intermediate files generated by .NET during the Build process.
- **`bin/`**: Contains the output files generated after the Build process, such as DLL files and other files required to run the application.

## File-scoped Namespace

A File-scoped namespace allows the namespace to be written without `{ }`.

Instead of:
```csharp
namespace CSharpBasicsAssignment
{
    // Code
}
```

We can write:
```csharp
namespace CSharpBasicsAssignment;
```
This removes one indentation level and keeps the code simpler.

# Part B — Variables, Types & Casting

Part B focuses on C# variables, data types, type conversions, casting, boxing, unboxing, and parsing.

The main method used for this part is:
```csharp
RunTypesDemo();
```

## 1. Variables and Data Types

The following C# types are demonstrated:
- `int`
- `long`
- `double`
- `decimal`
- `bool`
- `char`
- `string`
- `var`

Each variable is printed together with its runtime type using `.GetType()`.

**Example:**
```csharp
int age = 25;
Console.WriteLine($"int: {age}, Type: {age.GetType()}");
```

## 2. Implicit Conversion

An implicit conversion happens automatically when the destination type can safely represent the source value.

**Example:**
```csharp
int number = 100;
long bigNumber = number; // int is automatically converted to long
```

Another example:
```csharp
char letter = 'A';
int letterNumber = letter; // Character 'A' has the numeric value 65
```

## 3. Explicit Conversion

Explicit casting is required when converting between types where data may be lost.

**Example:**
```csharp
double value = 9.8;
int result1 = (int)value; // Result: 9 (truncation)
```
The `(int)` cast removes the decimal part. This is called **truncation**.

## 4. Convert.ToInt32

Another way to convert the value is:
```csharp
int result2 = Convert.ToInt32(value); // Result for 9.8 is 10
```
Unlike `(int)`, `Convert.ToInt32()` performs **rounding**.

## 5. Integer Division

```csharp
int division1 = 5 / 2; // Produces 2 (both operands are integers)
double division2 = 5.0 / 2; // Produces 2.5 (floating-point operation)
```

## 6. Boxing and Unboxing

Boxing happens when a Value Type is stored inside an `object`.

```csharp
int originalNumber = 50;
object boxedNumber = originalNumber; // Boxing

int unboxedNumber = (int)boxedNumber; // Unboxing
```

## 7. Parsing

A string containing a valid integer can be converted using:
```csharp
string validText = "42";
int parsedNumber = int.Parse(validText); // Result: 42
```

## 8. TryParse

`TryParse` can be used when the input might not contain a valid number.

```csharp
string badText = "abc";

if (int.TryParse(badText, out int tryResult))
{
    Console.WriteLine($"TryParse result: {tryResult}");
}
else
{
    Console.WriteLine("TryParse failed: 'abc' is not a valid integer.");
}
```
Instead of throwing an exception for invalid input, `TryParse` returns `false`.

## 9. Float to Decimal

The implicit conversion is not allowed:
```csharp
float floatNumber = 10.5f;
// decimal implicitConversion = floatNumber; // Compile error
```
The correct way is to use explicit casting:
```csharp
decimal decimalNumber = (decimal)floatNumber;
```

# Part C — Value Types vs Reference Types

Part C demonstrates the difference between Value Types and Reference Types using `struct`, `class`, Object references, Boxing/reference storage, and `ReferenceEquals()`.

## Struct Experiment

A `Point` struct is used:
```csharp
struct Point
{
    public int X;
    public int Y;
}
```

Execution:
```csharp
Point p1 = new Point { X = 1, Y = 2 };
Point p2 = p1;
p2.X = 99;
```
- **Result:** `p1.X = 1`, `p2.X = 99`
- **Explanation:** Assigning one struct variable to another copies the value. Changing `p2` does not change `p1`.

## Order Class

An `Order` class is created with 10 concrete-typed fields:

```csharp
class Order
{
    public int OrderId;
    public string CustomerName;
    public int Quantity;
    public decimal UnitPrice;
    public decimal TotalPrice;
    public bool IsPaid;
    public double DiscountPercent;
    public string ShippingCity;
    public char Priority;
    public long ItemCode;

    public void CalculateTotal()
    {
        TotalPrice = Quantity * UnitPrice * (decimal)(1 - DiscountPercent / 100);
    }

    public void PrintSummary()
    {
        Console.WriteLine($"OrderId: {OrderId}, Customer: {CustomerName}, TotalPrice: {TotalPrice}, IsPaid: {IsPaid}");
    }
}
```

## Reference Type Experiment

```csharp
Order o1 = new Order
{
    OrderId = 1001,
    CustomerName = "Mohamed",
    Quantity = 5,
    UnitPrice = 100m,
    TotalPrice = 0m,
    IsPaid = false,
    DiscountPercent = 10,
    ShippingCity = "Alexandria",
    Priority = 'H',
    ItemCode = 123456789
};

o1.CalculateTotal();

Order o2 = o1;
o2.IsPaid = true;
```
- `o2` does not create a new `Order` object; both variables refer to the same object in memory.
- Therefore, setting `o2.IsPaid = true` means `o1.IsPaid` also equals `true`.

## Object Reference Experiment

```csharp
object boxedOrder = o1;
Order o3 = (Order)boxedOrder;

bool sameReference = ReferenceEquals(o1, o3); // Returns True
```
Returns `true` because both references point to the exact same `Order` instance on the Heap.

## Stack & Heap Memory Model

Conceptually:

```text
STACK                         HEAP

o1 ────────────────┐
                   ├──────►  Order Object
o2 ────────────────┘
```

Both variables contain references pointing to the same object on the Heap. The complete diagrams are documented in `STACK_HEAP.md`.

# Part D — Scope & Operators

## D1 — Scope

### Static Fields Scope
A field can be accessed from multiple methods:
```csharp
private static int fieldValue = 50;

static void FieldScopeMethodOne()
{
    Console.WriteLine($"Method 1 can access fieldValue = {fieldValue}");
}

static void FieldScopeMethodTwo()
{
    Console.WriteLine($"Method 2 can access fieldValue = {fieldValue}");
}
```

### Local Variable Scope
A local variable is available only inside the method or block where it is declared.
```csharp
static void MethodScopeDemo()
{
    int localValue = 100;
    Console.WriteLine($"Local variable = {localValue}");
}
// localValue cannot be accessed outside this method
```

### Loop Scope
```csharp
for (int i = 0; i < 3; i++)
{
    int insideLoop = i * 10;
    Console.WriteLine($"Loop variable i = {i}, insideLoop = {insideLoop}");
}
// Console.WriteLine(i);          // Compile error
// Console.WriteLine(insideLoop); // Compile error
```

## D2 — Compound Assignment Operators

| Operator | Code Example | Equivalent Statement |
| :--- | :--- | :--- |
| `+=` | `total += 5;` | `total = total + 5;` |
| `-=` | `total -= 10;` | `total = total - 10;` |
| `*=` | `total *= 2;` | `total = total * 2;` |
| `/=` | `total /= 5;` | `total = total / 5;` |
| `%=` | `total %= 7;` | `total = total % 7;` |

## D3 — Bitwise Operators

Given operands `a = 12` (`1100` in binary) and `b = 10` (`1010` in binary):

### Bitwise AND (`&`)
```text
  1100  (12)
& 1010  (10)
------
  1000  (8)
```
*Result:* `8`

### Bitwise OR (`|`)
```text
  1100  (12)
| 1010  (10)
------
  1110  (14)
```
*Result:* `14`

### Bitwise XOR (`^`)
```text
  1100  (12)
^ 1010  (10)
------
  0110  (6)
```
*Result:* `6`

### `&` vs `&&`
- `&` is a **Bitwise AND** operator used to evaluate bit-by-bit comparisons.
- `&&` is a **Logical AND** operator used with Boolean expressions that supports **short-circuit evaluation** (if the left side is `false`, the right side is skipped).

# Part F — LeetCode 136: Single Number

## Problem
Given an integer array where every element appears twice except for one element that appears only once, find the element that appears only once.

**Examples:**
- `[2, 2, 1]` $
ightarrow$ `1`
- `[4, 1, 2, 1, 2]` $
ightarrow$ `4`
- `[1]` $
ightarrow$ `1`

## Solution

```csharp
public class Solution
{
    public int SingleNumber(int[] nums)
    {
        int result = 0;
        foreach (int num in nums)
        {
            result ^= num;
        }
        return result;
    }
}
```

### Why XOR?
XOR has two essential properties:
1. $x \oplus x = 0$
2. $x \oplus 0 = x$

Duplicate values cancel each other out:
$$2 \oplus 2 \oplus 1 = 0 \oplus 1 = 1$$

### Complexity
- **Time Complexity:** $O(n)$
- **Space Complexity:** $O(1)$

# Part G — Short Answers

### Question 1 — `.csproj` Configuration
The four core properties defined in the project file are:
1. `OutputType`: Configures output executable format (`Exe`).
2. `TargetFramework`: Specifies the runtime version (`net10.0`).
3. `ImplicitUsings`: Enables auto-imported standard namespaces.
4. `Nullable`: Enables Nullable Reference Type checks.

### Question 2 — Do `#region` and `#endregion` change the compiled output?
**No.** They are purely IDE directives used to collapse/expand code blocks for readability and have zero effect on the compiled binary or application behavior.

### Question 3 — When should `///` XML documentation comments be used?
`///` XML documentation comments should be used to document **Classes**, **Methods**, **Properties**, **Parameters**, and **Return Values**. They provide IntelliSense tooltips across projects.

Standard `//` comments are meant for internal implementation notes inside method bodies.

### Question 4 — Why does C# have no true global variables?
C# strictly enforces Object-Oriented paradigm rules; all state must reside within a type. The closest equivalent to a global variable is a **`static` field** inside a class.

```csharp
class Program
{
    private static int counter = 0;
}
```
